# WTD Text Verify

Актуализация и фактчек глав «Что мне делать? :-)» против живых внешних
источников (сайты, бенчмарки, продукты, дока). Две фазы, разделённые решением
автора: расследование + варианты → автор правит сам → верификация правок.

## When to Use

- Автор просит актуализировать секцию/главу под изменившийся внешний источник
  (сайт, бенчмарк, продукт закрыл или переименовал то, на что ссылается текст).
- Автор просит проверить его правки после push («git pull и проверь»).
- Нужен фактчек внешних ссылок, скриншотов и цифр в главах WTD.

## Источник правды

- Репо текста: `whattodo` (reference deployment), ветка `master`; авторские главы — `text/p*.md` и
  `text/index.md`. `text/books/` и `text/p3-references.md` — генерируемые,
  фактчеку не подлежат (правится генератор).
- Секция идентифицируется якорем `{#anchor}` в исходнике — заголовок может
  переименоваться, якорь сохраняется; все проверки ссылок вести по якорю.
- `git pull` — можно всегда; правки текста и push — только после явного
  решения автора. Текст авторский: моя роль — расследовать, предложить
  варианты с плюсами и минусами, дождаться выбора.

## Фаза 1 — расследование и варианты (до правок)

1. Прочитать целевую секцию из исходника в репо (`read_file` по
   `text/<chapter>.md`), не из веб-кэша и не с опубликованного сайта.
2. Найти причину изменения внешнего источника: сначала вендорский
   первоисточник (announcement, docs, changelog), затем вторичные обсуждения
   (аналитика, форумы), затем — живая страница.
3. Живую страницу проверять через `browser_exec` в DOM: селекторы, карточки,
   подписи фильтров, счётчики. `web_extract` на JS-тяжёлых страницах возвращает
   shell и навигацию — он для статей и доков, не для интерактива.
4. Бенчмарки и рейтинги живые (лидеры и карточки обновляются еженедельно):
   фактчек — только по живой странице, не по статьям и кэшу.
5. Предложить варианты правки (минимальный патч / рефрейм / гибрид), каждый с
   плюсами и минусами, плюс список открытых вопросов. Критерий качества
   предложения: формулировки, не привязанные к снапшоту UI (число моделей,
   дефолтные фильтры, цифры еженедельных лидеров); если конкретика нужна —
   в тексте обязан быть способ её воспроизведения читателем.

## Фаза 2 — верификация правок автора (после git pull)

1. `git pull`, затем `git log --oneline -5` и
   `git diff <old>..HEAD -- text/<file>`; `<old>` — последний коммит до пачки
   правок.
2. Внешний URL с якорем: `browser_exec` — искомый `id` есть среди
   `document.querySelectorAll('[id]')` и `window.scrollY > 0` после навигации
   с `#anchor`.
3. Скриншоты из текста (`text/img/*.png`): `vision_analyze` — описать, что на
   них, и сверить с живой страницей в той же конфигурации.
4. Утверждения о живой странице: проверять в DOM, в обеих конфигурациях —
   дефолтной и описанной в тексте.
5. Внутренние ссылки: каждая `chapter.md#anchor` должна иметь определение —
   `search_files` по `\{#anchor\}` в целевом файле. Особенно после
   рефакторинга соседних глав: переименованный заголовок с сохранённым якорем
   жив, а ссылки на анкор, исчезнувший при рефакторинге, — нет.
6. Грамматика: `make grammar` без аргумента — рабочее дерево против HEAD
   (чистое дерево → «no added lines, nothing written»);
   `make grammar <sha>` — новые строки с коммита (полный список режимов:
   `make help`). Диапазон по нескольким главам идёт дольше 10 минут — запускать
   в `terminal` с `background=true, notify=true` и доложить по завершении.
7. Отчёт автору: таблица «проверка → результат», наблюдения отдельно от
   ошибок; подтверждённое и найденное называть раздельно, без сглаживания.

## Грабли

- **Дефолт интерактивной страницы ≠ конфигурация скриншота.** Фильтры и
  селекторы по умолчанию показывают другой срез данных, и утверждение в тексте
  может быть невоспроизводимо по ссылке. Проверять утверждение в дефолтной
  конфигурации; если оно держится только на нестандартных настройках («включите
  все модели», другой индекс в селекторе) — инструкция читателю обязана быть в
  тексте, иначе утверждение врёт по ссылке.
- **Панели фильтров не всегда стандартные.** Открытый поповер искать по
  `[data-state="open"]`, `z-overlay`, дампить `innerText`; состояние чекбоксов —
  `input[type="checkbox"]` и счётчик `checked`. Не угадывать библиотеку
  компонентов по классам — искать открытую панель по состоянию.
- **Зрение — вторично.** Если `vision_analyze` недоступен (провайдер вернул
  ошибку роутинга модели), обходить DOM-дампом и не останавливать проверку:
  тексты карточек и подписи читаются из DOM надёжнее, чем с картинки.
- **Веб-кэш — устаревшие снапшоты.** `~/.hermes/cache/web/*.md` годится для
  поиска и чтения глав, но не для фактчека живых данных — там лежит прошлое
  состояние страницы.
